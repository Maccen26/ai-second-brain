# AGENTS INSTRUCTION

## PRIMARY GOAL 
The goal of this project is to create a small and local demo of a AI second brain. There are following constraints and requirements for the project:

1. The project will be a small personal project, with a focus on creating a second brain for AI.
2. There will be no user authentication or user scoped retrieval, and everything will be stored in a singl local Postgres database that is accessible to all users. (PORT WILL BE SPECIFED)
3. The project will be run locally
4. The project will be built within a time frame of around 8 hours, so each component must maximize simplicity, efficiency and value given I do not have a lot of time to build it.

Read the README.md for more information about the project, and the architecture choices.

## How to behave
If in doubt or if there is platns that are not alligned or clear with the primary goal in mind, please ask for clarification. you're allowed to push back on choices and ideas as long as you provide a clear explanation of why you think it is not aligned with the primary goal. 

Always ONLY implement the features that are required to achieve the primary goal. If you think a feature is not required, please ask for clarification before implementing it.

Always ONLY implement the features or code that were agreed upon. If extra features or code are needed to achive a subgoal, please ask for clarification and premission before implementing it. 


## How to code 

This mean that you use Objective Oriented Programming (OOP) principles, but avoid overengineering or adding unnecessary complexity. Use clear and descriptive variable and function names, and write comments (Only if needed) where necessary to explain the purpose of the code. 

Use single responsibility principle, and avoid creating classes or functions that do too much. Each class or function should have a clear and specific purpose, and should be easy to understand and maintain. 

Each method of a class should max be about 8 lines of code. 


## How to architect
The architecture will be screaming architecture, meaning that the architecture should be clear and easy to understand, and should not require a lot of documentation or explanation. We will split it up based on what it do and not what kind of object it is. This means that we will have a clear separation of concerns, and each component will have a clear and specific purpose.
